jevzip.

jevzip is a lossless compressor for bytes with a transformer of the Jev type. The encoder and the decoder divide the data into blocks of 512 bytes. The decoder decodes each block in K rounds, one round after the other. In each round, the decoder decodes a group of many bytes at the same time. One forward call calculates the probabilities of the 256 byte values for all the bytes in the group. An autoregressive model decodes only one byte in each round.

results

The test data is the standard enwik8 test split: the last 5 MB of enwik8 (English Wikipedia XML). The jevzip models have 11M parameters. Their training data is the first 90 MB of enwik8. The training time for each model was approximately 8 hours on the GPU of an M4 Pro computer.

Each jevzip size is the size of an actual compressed file. After each test, the decompressed file was the same as the original file, bit for bit. The LLM values are the ideal code lengths. The unit is bits per byte. A lower value is better. The last column shows the data that the decoder must have before it can decode: the model weights or the dictionary.

  • At 128 rounds, the jevzip file is 39% smaller than the xz file. It is 29% smaller than the xz file when xz also uses 64 MB of the training data.
  • cmix and paq8px give smaller files than jevzip at 128 rounds. They do not use model weights. The LLMs give much smaller files, but their weights are 15 to 45 times larger.
  • The jevzip AR control has the same size and the same number of training steps. Compared with it, the lanes file is 3% larger at 512 rounds, 7% larger at 128 rounds and 19% larger at 32 rounds.
  • The model weights are 22 MB. If you count the weights, jevzip gives a smaller total size than xz only for more than approximately 210 MB of data of the same type.
  • On the GPU of the M4 Pro, 16 rounds decode a 64 KB file 7 times faster than 512 rounds (2.0 s and 13.8 s). Each round needs at least approximately 6 ms, because the GPU starts many small operations and then waits for the probabilities.

description

A neural compressor calculates good probabilities for bytes, but its decoder is slow. An autoregressive model decodes only one byte in each round. Thus, for a block of 512 bytes, the decoder must do 512 rounds in sequence. Jev is a non-autoregressive model from TypeSafe AI. It calculates scores for a closed set of values for many slots at the same time. jevzip uses this method for entropy coding.

In each round, each byte in the current group becomes a slot. The model calculates the probabilities of the 256 byte values for all the slots at the same time. The blocks are in separate chains, and the decoder decodes all the chains at the same time. Thus, the dependency depth of a file is K × ceil(blocks / chains). jevzip decreases the K factor.

  1. Decode order. The decode order divides each block into K groups. In the lanes order, the block has 512/K lanes. The decoder decodes each lane from left to right. In each round, the decoder decodes one byte in each lane. When K = 512, the model is an autoregressive model. One model can decode with each K from 8 to 512.
  2. Two streams with the same weights. The content stream contains the decoded bytes. It uses causal attention and a KV cache. The slot stream has one query for each byte in the current group. A slot uses data from the decoded bytes and from itself, but not from the other slots. Thus, one forward call calculates the probabilities for all the bytes in a group, and the decoder calculates the same probabilities as the encoder.
  3. Probabilities for the byte values. Each slot can have one of the 256 byte values. The model compares each slot with the 256 byte embeddings. The model also uses these embeddings for the input bytes (tied embeddings).
  4. rANS. rANS changes the probabilities into bits. The encoder does the same forward calls as the decoder. Thus, the encoder and the decoder have the same probabilities, bit for bit.

procedure

Use these commands to install jevzip, get the weights and the test data, and do the benchmark test:

pip install -e ".[bench]"
python -m jevzip.fetch jevzip-lanes-11m-enwik8.pt && python -m jevzip.data enwik8
python -m jevzip.bench data/enwik8/test.bin --rounds 32 128 512 --verify

Use these commands to compress and decompress a file:

python -m jevzip c file.txt file.jz               # 128 rounds
python -m jevzip c file.txt file.jz --rounds 32   # 4 times fewer rounds, larger file
python -m jevzip d file.jz file.txt

limits

  • jevzip is a research tool. Do not use it to keep data.
  • To decode a file, use the same weights, torch build, CPU kernels and fp32 or bf16 setting as the encoder. A different torch version, or a GPU decoder for a CPU file, gives an incorrect result in the first 4 bytes. The header contains the model fingerprint. The rANS end-state check and a CRC find the other errors.
  • The encoder and the decoder are slow on a CPU: 2 to 10 KB/s.
  • Previous designs:
    • Two-stream attention (XLNet).
    • Any-order AR models (σ-GPT).
    • Parallel context models for neural image compression (checkerboard, M2T).
    • Neural compressors (NNCP, ts_zip, "Language Modeling Is Compression").
  • The author does not know a previous design that has all of these items:
    • Two-stream decoders with a KV cache.
    • One model for all numbers of rounds, from 8 to 512.
    • Block chains that the decoder decodes at the same time.
    This information can be incorrect. Examine it carefully.
