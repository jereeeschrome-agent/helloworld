jevzip.

jevzip is a lossless compressor for bytes. It uses a transformer of the Jev type. The decoder divides the data into blocks of 512 bytes, and it decodes each block in K rounds. In each round, the model calculates the probabilities of all 256 byte values for many bytes at the same time. An autoregressive model calculates only one byte in each step.

results

Three models have the same architecture with 5.0M parameters. The training time for each model was 120 minutes on a CPU with 4 cores. The training data is Python source code. The training for the lanes model used values of K from 8 to 512. Thus, one lanes model gives the results in all the lanes rows.

The training for the bitrev model used values of K from 8 to 128. The training for the linear model used only K = 512. The linear model is the autoregressive (AR) control. The test data is not in the training data. Each size in the table is the size of a real compressed file. After each test, the decompressed file was the same as the original file, bit for bit.

description

A neural compressor gives good predictions of bytes, but its decoder is slow. An autoregressive model does one step for each byte. Thus, a block of 512 bytes needs 512 sequential steps. Jev is a non-autoregressive model from TypeSafe AI. It calculates scores for a closed set of options for many slots at the same time. jevzip uses this method for entropy coding.

In each round, each byte that is not decoded becomes a slot. The model calculates the scores of all 256 values for all slots at the same time. The blocks are in independent chains, and all the chains decode at the same time. Thus, the dependency depth of a file is K × ceil(blocks / chains). jevzip decreases the K factor.

  1. Reveal order. The model divides each block into K groups. In the default lanes order, the block has 512/K lanes. The decoder decodes each lane from left to right. In each round, the decoder decodes one byte in each lane. When K = 512, the model is an autoregressive model.
  2. Two streams with the same weights. The content stream contains the known bytes. It uses causal attention and a KV cache. The slot stream has one query for each byte that is not decoded. A slot sees the known content and itself, but it does not see the other slots. Thus, the model calculates the scores for a full group in one pass.
  3. Scores for options. Each slot is a choice between the 256 byte values. The model compares each slot with the embeddings of the 256 values.
  4. rANS. rANS changes the scores into bits. The encoder does the same forward calls as the decoder. Thus, the encoder and the decoder have the same probabilities, bit for bit.

The reveal order has a larger effect than the number of rounds. The first design used a coarse-to-fine order (bit reversal). At 16 rounds on networkx, its first "anchor" bytes are 25% of the block. Each anchor byte uses approximately 4.4 bits, and the anchor bytes use 45% of all the bits. With the same quantity of calculation, the lanes model gives better results than the bitrev model. procedure

To compress and decompress a file, use these commands:

pip install -r jevzip/requirements.txt networkx
python -m jevzip c file.py file.jz               # lanes, 128 rounds
python -m jevzip c file.py file.jz --rounds 32   # 4 times fewer rounds, larger file
python -m jevzip d file.jz file.py
python -m jevzip.data --out data                 # training data and test files
python -m jevzip.bench data/networkx.py.txt --rounds 32 128 512 --verify

limits

  • The sizes do not include the model weights (approximately 10 MB). The model is useful only when it compresses a large quantity of data of the same type.
  • To decode a file, you must use the same weights, torch build, CPU kernels and thread count as the encoder. The header contains the model fingerprint and the thread count. If they are different, the decoder stops immediately. If the torch build or the CPU is different, the decoder finds the error only after it decodes the full file. The rANS end-state check and a CRC find this error. You cannot move compressed files between different CPUs.
  • Prior art: two-stream attention (XLNet), any-order AR models (σ-GPT), parallel context models for image compression (checkerboard, M2T) and neural compressors (NNCP, ts_zip). We do not know of a previous design with this combination: two-stream decoders with a KV cache, lane and bit-reversal schedules in one model, and block chains that decode at the same time. Examine this statement carefully.
