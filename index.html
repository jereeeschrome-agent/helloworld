jevzip.

A lossless byte compressor built on a Jev-style transformer. It decodes each 512-byte block in K parallel rounds. Every round scores all 256 byte values for many undecided bytes in one forward pass, instead of taking one model step per byte.

  • On held-out Python, sequential decoding beats xz -9e and brotli -q11: 1.453 vs 1.525 and 1.498.
  • On prose it doesn't. The training corpus is code.
  • Fewer rounds give a shallower decode and a bigger file. Lanes at 128 rounds is within 1.4% of xz with 4× fewer rounds than AR.
  • The ~10 MB model weights are not counted, the usual convention for pretrained compressors (brotli's built-in dictionary is not counted either).

rationale

Neural compressors predict bytes well, but decoding is slow: an autoregressive model takes one step per byte, so decode depth equals file length. Jev, TypeSafe AI's non-autoregressive model, scores a closed set of options for many slots at once. jevzip applies that idea to entropy coding. Each round, every undecided byte in a group becomes a slot, and the model scores all 256 values for all slots together.

  1. Reveal order. A block is cut into K groups. In the default lanes order, the block splits into 512/K lanes that are decoded left to right in lockstep, one byte per lane per round. K = 512 is plain autoregression.
  2. Two streams, shared weights. The content stream holds the known bytes under causal attention and is KV-cached. The slot stream has one query per undecided byte. A slot sees the revealed content and itself, never another slot. So a whole group is scored in one pass, and the decoder reproduces the same probabilities.
  3. Option scoring. Each slot is a typed choice over the 256 byte values, scored against tied embeddings.
  4. rANS turns the scores into bits. The encoder replays the decoder's exact forward calls, so both sides see bit-identical probabilities.

The reveal order matters more than the round count. The first design revealed bytes coarse to fine, in bit-reversal order. Its early "anchor" bytes are a quarter of the block, cost about 4.4 bits each and carried half of all bits. With the same compute, left-to-right lanes learn far faster. use

pip install -r jevzip/requirements.txt
python -m jevzip c file.py file.jz               # lanes, 128 rounds
python -m jevzip c file.py file.jz --rounds 32   # 4x fewer rounds, bigger file
python -m jevzip d file.jz file.py
python -m jevzip.bench data/networkx.py.txt --rounds 32 128 512 --verify

caveats

  • The model weights (~10 MB) aren't counted in the sizes. They only pay off when one model serves lots of similar data.
  • A file decodes only with the same weights, torch build, CPU kernels and thread count that encoded it. The header and a CRC catch any mismatch.
  • Prior art: two-stream attention (XLNet), any-order AR models (σ-GPT), parallel context models from learned image compression (checkerboard, M2T), and neural compressors (NNCP, ts_zip). The combination is the new part.
