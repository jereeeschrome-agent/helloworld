jevzip.

jevzip is a lossless compressor for bytes with a transformer of the Jev type. The encoder and the decoder divide the data into blocks of 512 bytes. The decoder decodes each block in K rounds, one round after the other. In each round, the decoder decodes a group of many bytes at the same time. One forward call calculates the probabilities of the 256 byte values for all the bytes in the group. An autoregressive model decodes only one byte in each round.

results

Three models have the same architecture with 5.0M parameters. The training time for each model was 120 minutes on a CPU with 4 cores. The training data is Python source code.

For the training of the lanes model, K was 8 to 512. Thus, one 5.0M lanes model gives the results in all the lanes rows without the † mark. For the training of the bitrev model, K was 8 to 128. For the training of the linear model, K was 512 only. The linear model is an autoregressive (AR) model, and it is the reference for the other models.

The test data is not in the training data. Each size in the table is the size of an actual compressed file. After each test, the decompressed file was the same as the original file, bit for bit. The unit is bits per byte. A lower value is better.

description

A neural compressor calculates good probabilities for bytes, but its decoder is slow. An autoregressive model decodes only one byte in each round. Thus, for a block of 512 bytes, the decoder must do 512 rounds in sequence. Jev is a non-autoregressive model from TypeSafe AI. It calculates scores for a closed set of values for many slots at the same time. jevzip uses this method for entropy coding.

In each round, each byte in the current group becomes a slot. The model calculates the probabilities of the 256 byte values for all the slots at the same time. The blocks are in separate chains, and the decoder decodes all the chains at the same time. Thus, the dependency depth of a file is K × ceil(blocks / chains). jevzip decreases the K factor.

  1. Decode order. The decode order divides each block into K groups. In the default lanes order, the block has 512/K lanes. The decoder decodes each lane from left to right. In each round, the decoder decodes one byte in each lane. When K = 512, the model is an autoregressive model.
  2. Two streams with the same weights. The content stream contains the decoded bytes. It uses causal attention and a KV cache. The slot stream has one query for each byte in the current group. A slot uses data from the decoded bytes and from itself, but not from the other slots. Thus, one forward call calculates the probabilities for all the bytes in a group, and the decoder calculates the same probabilities as the encoder.
  3. Probabilities for the byte values. Each slot can have one of the 256 byte values. The model compares each slot with the 256 byte embeddings. The model also uses these embeddings for the input bytes (tied embeddings).
  4. rANS. rANS changes the probabilities into bits. The encoder does the same forward calls as the decoder. Thus, the encoder and the decoder have the same probabilities, bit for bit.

The decode order has a larger effect than the number of rounds. The first design used a coarse-to-fine order (bitrev). At 16 rounds on networkx, its first "anchor" bytes are 25% of the block. Each anchor byte uses approximately 4.4 bits, and the anchor bytes use 45% of all the bits. With the same training time, the lanes model gives much better results than the bitrev model. procedure

Use these commands to install jevzip, compress and decompress a file, make the test data and do the benchmark test:

pip install -r jevzip/requirements.txt networkx
python -m jevzip c file.py file.jz               # lanes, 128 rounds
python -m jevzip c file.py file.jz --rounds 32   # 4 times fewer rounds, larger file
python -m jevzip d file.jz file.py
python -m jevzip.data --out data                 # training data and separate test files
python -m jevzip.bench data/networkx.py.txt --rounds 32 128 512 --verify

limits

  • The sizes do not include the model weights (approximately 10 MB). The model gives a smaller total size only when it compresses a large quantity of data of the same type.
  • To decode a file, use the same weights, torch build, CPU kernels and thread count as the encoder. The header contains the model fingerprint and the thread count. If they are different, the decoder stops immediately. If the torch build or the CPU is different, the decoder finds the error only after it decodes the full file. The rANS end-state check and a CRC find this error. You cannot decode a compressed file on a CPU that is different from the CPU of the encoder.
  • Previous designs:
    • Two-stream attention (XLNet).
    • Any-order AR models (σ-GPT).
    • Parallel context models for neural image compression (checkerboard, M2T).
    • Neural compressors (NNCP, ts_zip).
  • The author does not know a previous design that has all of these items:
    • Two-stream decoders with a KV cache.
    • The lanes order and the bitrev order in one model.
    • Block chains that the decoder decodes at the same time.
    This information can be incorrect. Examine it carefully.
